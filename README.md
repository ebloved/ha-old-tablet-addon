# Old Tablet Dashboard

Минималистичный дашборд для старых iPad (iOS 12 / Safari 12), которые больше не
тянут веб-интерфейс Home Assistant. Работает как аддон HAOS: общается с ядром
через Supervisor, админка открывается панелью в сайдбаре, а планшет ходит на
отдельный порт по токену.

## Зачем

- Companion app требует iOS 16.4+, фронтенд HA — современный JS. На iOS 12 не
  работает ни то, ни другое.
- Здесь клиент — обычная страница на ES2017: `fetch`, `EventSource`, CSS grid.
- Сервер держит токен HA у себя, кэширует RSS и отдаёт планшету только те
  сущности, которые есть на дашборде.

## Установка

1. Home Assistant → Настройки → Дополнения → Магазин дополнений.
2. Меню (⋮) → Репозитории → добавить URL этого репозитория.
3. Установить **Old Tablet Dashboard**, запустить.
4. В сайдбаре появится панель **Old Tablet** (только для администраторов).

## Настройка планшета

1. В админке навести камеру iPad на QR-код (iOS 11+ распознаёт QR прямо в
   «Камере»). Если адрес HA не определился — поправить поле «Адрес HA»,
   например `192.168.1.50`.
2. Safari откроет `http://<ha-host>:8088/?t=<token>`.
3. «Поделиться» → «На экран Домой» — страница откроется без адресной строки.
4. Настройки → Экран и яркость → Автозаблокировка → **Никогда**.
5. По желанию: Guided Access (тройной клик по Home) как kiosk-режим.

Порт `8088` публикуется на хост, поэтому доступен только в локальной сети.
Токен даёт управление устройствами — не публикуйте ссылку.

Токен остаётся в адресе страницы (`?t=…`) намеренно: ярлык на экране «Домой»
сохраняет URL целиком, а standalone-приложения на iOS не всегда видят
localStorage Safari. Внешние ссылки из RSS открываются с `rel=noreferrer`,
поэтому токен не утекает в Referer.

## Виджеты

| Тип | Что делает |
|---|---|
| `entity` | плитка switch/light/cover/fan и т.п., тап переключает |
| `sensor` | значение + единица измерения, только чтение |
| `clock` | часы и дата, считаются на клиенте |
| `rss` | лента новостей, тянется и кэшируется сервером |

## Редактор

В админке — визуальный холст, а не таблица:

- перетаскивание плиток меняет порядок, сетка переливается;
- угол выделенной плитки тянется мышью/пальцем — меняются `w`/`h`;
- справа инспектор: тип, сущность с автодополнением, подпись, лента, размеры;
- пресеты устройств (9.7", 10.2", 10.9", 12.9", свои пропорции) задают
  пропорции холста и число колонок;
- тема `dark`/`light` переключается там же и применяется к планшету.

Сетка на планшете фиксированная: `columns` колонок по 92 px, поэтому превью
в редакторе совпадает с тем, что на стене. `w` — 1..columns, `h` — 1..6.
Незаполненные виджеты сохраняются как черновики и показываются на планшете
пустыми — чтобы не терять работу.

Конфиг хранится в `/data/config.json` и попадает в снапшоты HA. Сохранение
рассылает событие по SSE — планшет перерисовывается без перезагрузки.

## API

```
GET  /api/config          конфиг без токена
GET  /api/state           состояния только нужных сущностей
GET  /api/events          SSE: state_changed + config
POST /api/action          call_service (whitelist доменов и сервисов)
GET  /api/rss?id=...      распарсенный фид из конфига
GET  /healthz             для watchdog Supervisor
```

Все `/api/*` на порту планшета требуют `X-Dash-Token` или `?t=`.

## Разработка

```sh
cd wall-dashboard
DASH_DATA=./data HA_URL=http://homeassistant.local:8123 HA_TOKEN=... \
  INGRESS_ADDR=:8080 TABLET_ADDR=:8088 go run ./cmd/dash
```

Админка в dev-режиме: `http://localhost:8080/admin` (на ingress-листенере она
без пароля, потому что в проде этот порт не публикуется).

Сборка образа для локального аддона:

```sh
docker build --build-arg BUILD_FROM=ghcr.io/home-assistant/amd64-base:3.20 \
  -t local/old-tablet-dashboard:0.1.0 wall-dashboard
```

## Скрипты, сцены, кнопки

Виджет `entity` работает и с action-сущностями. Тап по плитке вызывает
`script.turn_on`, `scene.turn_on`, `button.press` или `input_button.press`;
для света и прочего — `toggle`, для штор — `open_cover`/`close_cover`.
На плитке показывается «Run» и время последнего запуска.

## Автоматизация темы

Аддон слушает событие `old_tablet_dashboard_theme` и сохраняет тему. Значит,
её можно переключать автоматизацией:

```yaml
alias: Dashboard theme at sunset
triggers:
  - trigger: sun
    event: sunset
actions:
  - event: old_tablet_dashboard_theme
    event_data:
      theme: dark
```

Симметрично на `sunrise` — `theme: light`. Тема применяется без перезагрузки
планшета (SSE) и переживает рестарт аддона. Событие можно отправить и руками
из «Инструментов разработчика» → «События».

## Ограничения

- Только HAOS / Supervised: аддонам нужен Supervisor.
- Safari 12: без service worker, без Wake Lock API. Поэтому автоблокировка
  выключается вручную, а страница сама перезагружается ночью и при мёртвом SSE.
- HTTPS не используется на порту планшета: это LAN. Если нужен TLS — ставьте
  перед аддоном reverse proxy.

## Если в логе `SUPERVISOR_TOKEN is empty`

Базовый образ Home Assistant запускается через s6-overlay, а s6 не прокидывает
переменные окружения контейнера в legacy-сервисы. Поэтому в `Dockerfile` стоит
`ENTRYPOINT []`: бинарник стартует напрямую и видит `SUPERVISOR_TOKEN`. Если
форкаете образ — не убирайте эту строку и не возвращайте s6 в качестве
entrypoint.
